# Council helper commands

The Chair uses `council` for mechanical steps. Run council help for exact syntax;
the stage doctrine says when each command belongs in a run.

How to call it (a plain `council <command>`) is context-core's, The helper.

Every command takes its input by argument or file path, never by stdin: nothing is piped into
`council`, and a permission rule that refuses pipes costs nothing.

Build proof uses `council gate before-<id>` and `after-<id>` with the same command, where the id is
the task's number; `${CLAUDE_PLUGIN_ROOT}/references/build-proof.md` gives the modes
(`--proof preserve`), limits and verdicts.

| `council route recommend --task "<summary>" --mode <mode>` | `<mode>` is the skill's name, as for `run open` (`council-review`); inspect an advisory size, risk, seat archetypes, verification and budget (at the mode's per-role estimates) before opening a run; use `--classic` for the fixed comparison path (see `${CLAUDE_PLUGIN_ROOT}/references/run/adaptive-routing.md`) |
| `council run events show` · `run events check` · `run events repair` | inspect or validate the run's mechanical event history (`events.tsv`), or mend a torn last line (a byte copy is kept); see `${CLAUDE_PLUGIN_ROOT}/references/run/event-stream.md` |
| `council run audit [--run <folder>] [--transcript <session .jsonl>]` | after the close, check the run against the method: stages in order, agents on record while they ran, one check at a time, the deliverable, the claim index, every seat, every agent seat's token figure (a FAIL names each seat with none and why), the agent limit, a push let past the freeze (a warning) — and, from the session transcript (found by the run's session id when `--transcript` isn't given), the size and cost recorded (`council state size=`) before the first dispatch, both status cards, the rulings at Deliver as one question, the plain `council` call, no `\| tail`/`\| head`, refusals (a call that exited 2) tried again, and a `council:` line whose exit a chained or piped call hid. Pass, warn or FAIL per item; exit 1 on a FAIL; reads only (the close alone saves its report, as `<run>/audit.md`) |
| `council run export --anon <run> <dest> [--transcript <session .jsonl>]` | copy what the audit reads of a run (a run folder, or a run's name) into a new or empty folder outside it, anonymised: absolute paths as `<project>`, `<home>`, `<plugin>` or `<path>`, session ids as `session-<n>`, e-mail addresses and the login name stood in for, and the user's words, the Chair's notes and every free word of a command as stand-ins of the same shape (each letter x, each digit 0); times kept; synthesis.md, verify-*.md and audit.md with their contents left out; the session transcript's part for the run as `transcript.jsonl`. For a replay fixture or a bug report. `--anon` is required, and the copy never writes over a file |
| `council state key=value …` | update the run's state header: phase, next, size, deliverable, waiting, input (a build's plan, review or post-game) — never what `run open`, `run resume` or `run close` writes (mode, opened, code-root, session, the schemas, start-head, closed, actual), refused naming the command that does; `decision="<the user's words>"` goes under Decisions so far (redacted), and the card shows the latest; with `task=<n>` (task-3, T3 or 3, a task of the build's plan) it is that task's alone, and only that task's orders carry it beside the whole run's (an entry with no task is the whole run's). It unlocks only that task's gates — its `NEEDS: fix` stop, its third check, its third fix round; Full size and one checker per batch count the whole run's decisions only. A builder already running when the user decides has its orders already: tell the user, and the task's next round carries it. A stage change records that stage's next step unless the call names one. `phase=` takes a stage name (convene … learn, or build), refused when empty or unknown, or when it would pass over a stage the mode must enter — `skip="<why>"` allows that, and the phase event records it; `waiting="<question>"` prints a reminder to alert the owner with `council status --line` |
| `council seat <slug> <state> [agent=… tokens=… agents=…]` | record a worker's state, and once per finished agent run its usage: the id the tool returned, the notification's figure as given, a Workflow's agent count (`${CLAUDE_PLUGIN_ROOT}/references/run/run-accounting.md`); prints the progress line to relay — and, at the run's first dispatch only, a reminder to show the user the run's status, which marks the run's card due until `council status` reads it; a build task's third check (`verify-<n>c`, or `verify-<n>` started again) is refused until a `diagnose-<n>` seat or a decision of the user's is on record after the second verdict. In a build, `task-<n>` is the build seat: it is refused while another build seat is queued or running, and while a `NEEDS: fix` stop on its task or on a task it depends on (the `input=` plan's `Depends on`, all the way down) stands — until a decision of the user's is on record from the stop's minute on, or the stopped task's `after-<n>` gate passes after the stop. The stop is read from the seat's note whatever its state (`NEEDS: Fix` or `**NEEDS:** fix` alike): recorded `failed` or `skipped` it still stands, and a new `note=` on a seat whose stop stands is refused; its `done` needs `report-<n>.md` unless its note starts `NEEDS:`, and its start names the files changed outside a saved round. A seat's `NEEDS:` note ends when the seat has run again and is recorded `done` with no `note=` |
| `council run turn-end --session <id>` | the turn-end hook's decision (`hooks/turn-end.sh`): a run this session drives, with no seat running, waits on the user — recorded as `waiting`, and the Chair is sent back once to alert the owner (a wait the Chair recorded itself was asked for then: one alert per wait); the next seat, gate, stage or status change, the user's go (`cap allow`, `repair allow`) or a decision ends the wait; while the run's first card is still due, the Chair is also sent back once to show it, a seat working or not |
| `council cap` · `cap allow <n> --user-said "…"` · `cap check` | where the run stands against its agent cap and token ceiling, and whether new agents are stopped · record the user's go past them, in their words: n more agent runs may start · the agent gate's decision, for `hooks/agent-gate.sh` (exit 2 while stopped); given the tool about to start, a pass counts one agent start, for the run the dispatch names, else the newest run this session drives; given `type=` (a `council-worker` or `council-verifier`), `seat=`, `run=` and `file=` as the hook reads them from the dispatch, refuses that agent while the council home (`.council/`) or the run the dispatch names can't be written from this session (a file is tried; the reason names the folder and says to open the session in the main checkout or fix the permissions), with no open run for it, for a closed or paused run while none is open here, for a seat the plan doesn't select (the `Seat:` line's, else the written file's), or as a build task's third check; a `council-builder` goes out only while its build seat is queued — one whose dispatch names no build seat (no `Seat: task-<n>` line and no one `report-<n>.md`), or a seat more than one open run selects, is refused, naming how to dispatch it — and its pass records the seat `running` (no agent id yet), so a second builder for that seat, sent with it or before `council seat task-<n> running agent=<id>`, is refused (a dispatch that started no agent: `council seat task-<n> failed note="dispatch failed"`, then `queued`) |
| `council index [--base <ref>]` | build the change index |
| `council evidence build` · `evidence check` · `evidence show` | index synthesis claims, support states, provenance and verifier links in run-local `claims.jsonl`; rebuild after Challenge, then check for missing or stale links and a cut claim a verifier found true (see `${CLAUDE_PLUGIN_ROOT}/references/run/evidence-model.md`) |
| `council repair record <task> <gate>` · `repair show|check [task]` · `repair allow <gate> --user-said "…"` | record and inspect a build's bounded gate-repair trail without running a gate or changing code; in a build each gate run records itself (a failure is an attempt on the task whose build seat `task-<n>` runs, else the task `next:` names, a pass closes the trail), and a gate stopped at three failures runs again only after `repair allow` records the user's go (see `${CLAUDE_PLUGIN_ROOT}/references/run/repair-loop.md`) |
| `council gate <name> [-- '<command>']` · `council gate --all --at grounding` (or `verify`) | run one gate (an ad-hoc one: quote the whole command) or the configured set, judged by exit code, output saved. From `--all`, **exit 4 = NOTHING WAS CHECKED** — no gate ran (context-core, The helper). From a single gate, 4 is that command's own exit code. A run takes one gate call at a time: while one runs, a second is refused (exit 2, "checks are already running") and writes nothing — wait for the first, never start another copy; `council gate --wait <name>` queues behind it (20 minutes, or `--wait=<seconds>`). Run one gate per Bash call. **Every gate has a time limit:** `--timeout <time>` (`900`, `15m`) when given; else the largest of three times its own green baseline in this run (a red baseline's time doesn't count), the config's `- gate time limit: <time>` under Run preferences (read at every call, so adding it raises a limit at any time) and 120 s; with neither a green baseline nor that line, 9 minutes for a check given its command after `--` (it borrows no other gate's time) and 30 minutes for a configured gate. Past it the gate and every process it started are stopped, and it is recorded as exit 124, `TIMED OUT` (its verdict json says `"timed_out": true`, and every verdict keeps its `"limit"`): a failure and a repair attempt, never a pass or a proof. **A green is not run twice on the same files:** every gate's verdict also keeps the tree it ran on (`"tree"`: every file on disk, committed, staged or not, untracked included, each as its bytes on disk, so a line-end-only edit counts; what git ignores, `.council/` and Python's bytecode left out, and no tree while a submodule has changes) and who ran it (`"seat"`: `--seat <slug>`, else `chair`). `gate --all` doesn't run a gate whose last run here was green, with the config's command, on the very tree the code root holds now: it says so in one line naming the seat and the tree, and `--rerun` runs it anyway. A red, a time-out, a pass with nothing run, another command under its name or any change to the files (an uncommitted edit, a new file, integration) means it runs. **A gate may name the paths it covers:** an optional `Covers` column in the Gates table, git pathspecs from the code root, comma separated (`app/ui/, *.kt`; an example row is in `references/templates/council.config.md`); an empty cell, or no column, is the whole tree. Then `gate --all` doesn't run it when nothing under those paths differs between its last green's tree and the files now: one line, `gate ui: not rerun — nothing under app/ui/, *.kt changed since its green run (<seat>, tree <id>, <time>); saves <its run time>`, and the receipt reads `ui: pass → pass (not rerun)`, with that reason under `Not proved:`. A tree git can't read, or a Covers path that matches no file, means it runs; `--rerun` runs it anyway; `council doctor` warns of a Covers path that matches no file. A builder in its own worktree runs `council gate <name> --seat <slug>`: the gate runs in the working tree it is called from, and its record is the run's record of that gate |
| `council gate <name> --invalid "<why>"` | mark a red that proves nothing — the new check didn't compile, the probe was broken — on its record, with the reason; nothing runs. `council check` then reads that `before-<n>` or `regress-<n>` as `NO-PROOF-YET`; fix the check, compile it, run the gate again. A repair attempt it counted stays counted |
| `council changed [--glob '<pat>'] [--each] -- <cmd>` | run `<cmd>` over just the files this change touches — committed since the base, staged, unstaged and new; exit 0 when none matched, so a newly fitted check is green on day one. Inside a gate the base is the run's recorded one (`council index`); it says which base it used |
| `council collect` · `council check` | check the seat files — the brief's, a war room's debate.md's, and any other `.md` in `seats/`, which a Workflow's agents may have written past the seat-check hook · check citations (the run's own files too), origin and request quotes — and a build's declared change or preservation proof, including the saved test (see `references/build-proof.md`). A before-check that was marked invalid, timed out, or never ran (exit 127) is `NO-PROOF-YET`; a proof that ran only scripts in the run folder is noted. An `ok` change proof of a task with saved rounds is rerun in a scratch copy, first with the change on, where it must pass (else the copy can't run it: not made), then with every round saved since the task's first taken off, newest first (its tests and every round file its command names kept), where it must fail: one that still passes is `REVERT-PASSED`, one that can't be made is said and goes under `Not proved:`. A control that fails when the after-check ran on other files is `AFTER-STALE` (run that after-check again); a change proof whose after-check ran no test is `NOTHING-RAN`; a proof with no saved round, or a gate, that ran on other files than those on disk now is named under `Not proved:`. A build's check ends with three receipt lines from the records, just before its closing line and in `check.md`: `Checked by machine:` (each gate, baseline → now), `Not proved:` and `Your decisions:` (each of the user's decisions, a task's marked `task <n>:`, or `none`) (`references/build-proof.md`, The receipt lines). `council collect` also warns, on stderr, about each of the whole run's decisions recorded before `brief.md` was last written that the brief does not carry word for word (line breaks, curly quotes and case aside); `council state phase=work` gives the same warning before any seat is dispatched. On a just-me council, in a build, it also names each council reference — a `.council/` path, a run folder, `ruling <n>`, `verify-<n>`, and in comments and prose a D-, F-, AP- or EC- id or "(task <n>)" — in what the build added since it opened: lines, untracked files changed since, commit messages not yet pushed, and a PR body drafted as `<run>/pr-body.md`; each is a failure, counted apart from citations (`references/run/sharing.md`) |
| `council patch save <n> [<report>] [--base <rev>]` · `patch show <n>` · `patch apply\|revert <n> [--round <r>]` · `patch hold <n>` · `patch apply <n> --held` | in a build, at each round's report: read the head of `<run>/report-<n>.md` (Cause with its state, Owner, Removed, Assumed), save the round's diff (every file on disk but what git ignores, `.council/` and Python's bytecode, `__pycache__/` and `*.pyc`) and record under `<run>/patches/`, and check them against each other before the verifier sees either — refused, nothing saved, for a missing or malformed head, a fix with no cause or one not yet `OBSERVED`/`REPRODUCED`, a removed test, assertion or document rule the head's Removed line doesn't name, or a third fix round in the same files without a `Redesign:` line and the user's go (a second save by the builder at work, its seat `task-<n>` not recorded finished since its round, replaces that round: same number, no fix round); files are named as written (git's path quoting off); files outside the task's slice (the `input=` plan's Owner and Touches) and lines that look like a workaround are listed for the verifier as questions · print the task's history across its rounds (`patches/T<n>.md`), each round with the gates that went red since the save before it · put a saved round (the task's last unless `--round`) back on the code root's files, or take it off: all or nothing, refused with nothing changed and the files named when it won't go cleanly; no record changes, and the next `patch save` diffs from the last saved round as before · write the edits no round holds (what the next `patch save <n>` would save) to `<run>/patches/T<n>-held.patch` and take them off the files, all or nothing; with nothing to hold it says so, exit 0 — a builder stopping with `NEEDS:` does this first · put them back and remove the file, refused with nothing changed, naming the file, when they no longer go on cleanly. See `${CLAUDE_PLUGIN_ROOT}/references/run/builder-report.md` |
| `council context build task-<n>` | in a build, a task's orders for its builder, from the run's files and printed (never written; the builder runs it as its first command; the Chair adds only where to start and what worries it, in the dispatch's `Start:` line): under its heading the run folder, the code root and what the task's next round is judged against (the last saved round's tree, else the commit the run opened on), and a `Held:` line when the task has held edits (`council patch apply <n> --held`), then six `## ` parts — the task (its Serves quote as the plan writes it, Done when, the Rests on facts with their states, and a `NEEDS:` note on its seat as `Stopped earlier:`); its Owner, the map's one-way-per-job row it names, the slice `council patch save` judges, the other map rows inside its Touches, what it must not touch, its Ref and Domain; the config's `## Hard rules` word for word, its Constraints and the memory entries in scope for the slice; the user's decisions (the whole run's and the task's own, never another task's), the `## Later` words of ask.md and of the filed request it continues, the gates, the time limit, its proof gates (`before-<n>`, `after-<n>`, `references/build-proof.md`) and the standing builder rules (`references/run/builder-rules.md`), the plugin's files by their whole path; other tasks' saved rounds on the same files, with their causes, and, once the task has a saved round, its own history `patches/T<n>.md` by path; and what was left out. At most 8,000 bytes: over that, whole parts go from the end and are named under `## Left out`; the last line is `pack: <bytes> bytes of 8000; left out: <parts> \| nothing`. The tasks come from `<run>/tasks.md` when it is there (a review's selected findings, written by the Chair in the plan's task format under `## Task Sequence`; `input=` stays the review's path), else from `input=`: a plan's `## Task Sequence` or a post-game's `### Next tasks` (`#### <n>.`). Refused, naming the next step, with no open run, no `input=`, an input that can't be read, one that lists no tasks (naming `<run>/tasks.md` and `references/run/run-plan.md`, Plan tasks; `council seat task-<n> queued` is refused the same way), or a task it doesn't have (task-3, T3 or 3) |
| `council tree` | the build's task tree, printed: the request in the user's words (the filed request the run continues, then ask.md's), then the build's tasks (as `context build` reads them) under the Serves quote each gives, in plan order, each with the tasks its `Depends on` row names (`depends on T1, T3`), how many facts it rests on, its `before-<n>`/`after-<n>` gates (pass or fail), its saved rounds, the log's Converge result (`converge:`), and the `NEEDS:` note of a seat named for it (`task-3`, `T3`), as `was stopped: NEEDS: …` once the task's `after-<n>` gate has passed after the stop (with no event stream, its last verdict is a pass). ## The council home

The main checkout's `.council/` (`council home` prints it), even from a linked worktree.

| Under the council home | What | Git |
|---|---|---|
| `council.config.md` · `conventions.md` · `map.md` | roster, gates, run preferences · memory · codebase map | tracked |
| `cards/<slug>.md` · `ledger.tsv` | a seat translated to this project, written the first time a run selects it · each seat's record, a row per completed run | tracked |
| `plans/` `reviews/` `logs/` `research/` `postgames/` `refs/` | deliverables · project-local seat docs | tracked |
| `asks/` | the user's requests, word for word — every deliverable points at its own | local — to share them, replace the `asks/` line in `.council/.gitignore` with `!asks/` |
| `runs/<date-time>-<mode>/` | `session-state.md` `run-plan.tsv` `events.tsv` `ask.md` `log.md` `seats.tsv` `usage.tsv` `gates/` `debate.md`, and what each stage leaves (context-core, The stages) | ignored |
