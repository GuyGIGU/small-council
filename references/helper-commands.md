# Council helper commands

The Chair uses `council` for mechanical steps. Run council help for exact syntax;
the stage doctrine says when each command belongs in a run.

Call it as a plain `council <command>` — never through a shell variable or alias, and never as
`bash <path>/bin/council` while `command -v council` succeeds. Permission rules match the command
text, so any other form asks the user every time. Only if it isn't on PATH, write
`bash "${CLAUDE_PLUGIN_ROOT}/bin/council" <command>` out in full each time, never via a variable.

Build proof uses `council gate before-<n>` and `after-<n>` with the same command. The default is a
failing-before/passing-after change check. `--proof preserve` on both gates records a refactor's
invariants passing on both versions; declare that choice before editing. See
`${CLAUDE_PLUGIN_ROOT}/references/build-proof.md` for limits and verdicts.

| Command | Use it to |
|---|---|
| `council run open <mode> [--code-root <worktree>]` · `run status [--all]` · `run close [--status …]` · `run resume` | open a run and its starter plan (prints its folder; refuses a second in-progress run on this tree without `--alongside`; with the code in a worktree, open it from the main checkout with `--code-root`, and later commands find it by this session — never drive a run from a session isolated in a worktree, which can't write the council home) · list runs · close one — `complete` is refused until the run has come through Deliver (after any step back to an earlier stage, again), so a paused one closes `--status paused` — then, with Python 3.8+, its audit's FAIL lines and a reminder to show the user its closing card (`council status --widget --run <folder>`) · carry one on in this session (see Resume) |
| `council run plan check` · `run plan show` | validate the run's routing, context, budgets and verification contract — a Full plan only once a decision of the user's since the run opened is on record (`council state decision="…"`) · show those decisions plainly |
| `council route recommend --task "<summary>"` | inspect an advisory size, risk, seat archetypes, verification and budget before opening a run; use `--classic` for the fixed comparison path (see `${CLAUDE_PLUGIN_ROOT}/references/adaptive-routing.md`) |
| `council run events show` · `run events check` · `run events repair` | inspect or validate the run's mechanical event history (`events.tsv`), or mend a torn last line (a byte copy is kept); see `${CLAUDE_PLUGIN_ROOT}/references/event-stream.md` |
| `council run audit [--run <folder>] [--transcript <session .jsonl>]` | after the close, check the run against the method: stages in order, agents on record while they ran, one check at a time, the deliverable, the claim index, every seat, the agent limit — and, from the session transcript (found by the run's session id when `--transcript` isn't given), both status cards, the plain `council` call, no `\| tail`/`\| head`, refusals tried again. Pass, warn or FAIL per item; exit 1 on a FAIL; reads only; optional Python 3.8+ |
| `council state key=value …` | update the run's state header: phase, next, size, deliverable, waiting; `decision="<the user's words>"` goes under Decisions so far (redacted), and the card shows the latest. A stage change records that stage's next step unless the call names one. `phase=` takes a stage name (convene … learn, or build), refused when empty or unknown, or when it would pass over a stage the mode must enter — `skip="<why>"` allows that, and the phase event records it; `waiting="<question>"` prints a reminder to alert the owner with `council status --line` |
| `council seat <slug> <state> [agent=… tokens=… agents=…]` | record a worker's state, and once per finished agent run its usage: the id the tool returned, the notification's figure as given, a Workflow's agent count (`${CLAUDE_PLUGIN_ROOT}/references/run-accounting.md`); prints the progress line to relay — and, at the run's first dispatch only, a reminder to show the user the run's status, which marks the run's card due until `council status` reads it; a build task's third check (`verify-<n>c`, or `verify-<n>` started again) is refused until a `diagnose-<n>` seat or a decision of the user's is on record after the second verdict |
| `council run turn-end --session <id>` | the turn-end hook's decision (`hooks/turn-end.sh`): a run this session drives, with no seat running, waits on the user — recorded as `waiting`, and the Chair is sent back once to alert the owner (a wait the Chair recorded itself was asked for then: one alert per wait); the next seat, gate, stage or status change, the user's go (`cap allow`, `repair allow`) or a decision ends the wait; while the run's first card is still due, the Chair is also sent back once to show it, a seat working or not |
| `council cap` · `cap allow <n> --user-said "…"` · `cap check` | where the run stands against its agent cap and token ceiling, and whether new agents are stopped · record the user's go past them, in their words: n more agent runs may start · the agent gate's decision, for `hooks/agent-gate.sh` (exit 2 while stopped); given the tool about to start, a pass counts one agent start; given `type=` (a `council-worker` or `council-verifier`), `seat=` and `run=` as the hook reads them from the dispatch, refuses that agent with no open run for it, for a closed or paused run, for a seat the plan doesn't select, or as a build task's third check |
| `council index [--base <ref>]` · `council impact` | build the change index and, when Python 3.8+ is available, the bounded `impact.tsv` graph · refresh that graph after code changes (see `${CLAUDE_PLUGIN_ROOT}/references/impact-graph.md`) |
| `council context build <seat> [--expand PATH …]` · `council context show <seat>` | after `brief.md`, select a seat's context at its validated run-plan level · inspect its path and selection metrics (see `${CLAUDE_PLUGIN_ROOT}/references/precision-context.md`); optional Python 3.8+, with brief-only fallback |
| `council evidence build` · `evidence check` · `evidence show` | index synthesis claims, support states, provenance and verifier links in run-local `claims.jsonl`; rebuild after Challenge, then check for missing or stale links and a cut claim a verifier found true (see `${CLAUDE_PLUGIN_ROOT}/references/evidence-model.md`); optional Python 3.8+ |
| `council repair record <task> <gate>` · `repair show|check [task]` · `repair allow <gate> --user-said "…"` | record and inspect a build's bounded gate-repair trail without running a gate or changing code; in a build each gate run records itself (a failure is an attempt on the task `next:` names, a pass closes the trail), and a gate stopped at three failures runs again only after `repair allow` records the user's go (see `${CLAUDE_PLUGIN_ROOT}/references/repair-loop.md`); optional Python 3.8+ |
| `council gate <name> [-- '<command>']` · `council gate --all --at grounding` (or `verify`) | run one gate (an ad-hoc one: quote the whole command) or the configured set, judged by exit code, output saved. From `--all`, **exit 4 = NOTHING WAS CHECKED** — no gate ran; say so, never report it as a pass. From a single gate, 4 is that command's own exit code. A run takes one gate call at a time: while one runs, a second is refused (exit 2, "checks are already running") and writes nothing — wait for the first, never start another copy. Run one gate per Bash call. **Every gate has a time limit:** `--timeout <time>` (`900`, `15m`) when given; else three times its baseline time in this run, at least 120 s — for a check given its command after `--`, three times the run's slowest baseline gate; else the config's `- gate time limit: <time>` under Run preferences; else 30 minutes. Past it the gate and every process it started are stopped, and it is recorded as exit 124, `TIMED OUT` (its verdict json says `"timed_out": true`, and every verdict keeps its `"limit"`): a failure and a repair attempt, never a pass or a proof |
| `council gate <name> --invalid "<why>"` | mark a red that proves nothing — the new check didn't compile, the probe was broken — on its record, with the reason; nothing runs. `council check` then reads that `before-<n>` or `regress-<n>` as `NO-PROOF-YET`; fix the check, compile it, run the gate again. A repair attempt it counted stays counted |
| `council changed [--glob '<pat>'] [--each] -- <cmd>` | run `<cmd>` over just the files this change touches — committed since the base, staged, unstaged and new; exit 0 when none matched, so a newly fitted check is green on day one. Inside a gate the base is the run's recorded one (`council index`); it says which base it used |
| `council collect` · `council check` | check the seat files — the brief's, a war room's debate.md's, and any other `.md` in `seats/`, which a Workflow's agents may have written past the seat-check hook · check citations (the run's own files too), origin and request quotes — and a build's declared change or preservation proof, including the saved test (see `references/build-proof.md`). A before-check that was marked invalid, timed out, or never ran (exit 127) is `NO-PROOF-YET`; a proof that ran only scripts in the run folder is noted. On a just-me council it also names each council reference — a `.council/` path, a run folder, `ruling <n>`, `verify-<n>`, and in comments and prose a D-, F-, AP- or EC- id or "(task <n>)" — in the change's added lines since the run's base, its commit messages and a PR body drafted as `<run>/pr-body.md`; each is a failure (`references/sharing.md`) |
| `council ask save [slug]` | file the run's ask.md — the user's words — under `.council/asks/`, redacting secrets; records `ask=` |
| `council home` · `home rule` | where the council lives (the main checkout's `.council/`) · the Edit permission rule for that folder, in the form Claude Code matches — council-init offers it |
| `council sharing` · `sharing just-me` · `sharing team` | who sees the council, and what is out of line with it · keep it on this machine: git ignores `.council/` through its own exclude list (never committed or pushed), the CLAUDE.md / AGENTS.md note goes, the config says `- sharing: just me` · undo that; council files already in git are the user's to take out, with the command it prints |
| `council fingerprint check` · `council memory select` · `council prior` | a changed stack · the memory entries in scope · earlier council work on these paths |
| `council memory propose claim\|repair <id>` · `memory accept\|reject F-<n> --user-said "…"` | at Learn: draft an observed failure from the run's verified record under `## Proposed` · file the user's answer in their words; optional Python 3.8+ |
| `council status [--widget\|--line]` · `council correct <seat> …` | the run in plain words for the user: a widget card, one notification line, or text ending with the terminal view's command (each clears the run's card-due mark; `--json` doesn't) · lay an exact, evidenced figure over a seat's record |
| `council pet` · `council pet --stop` | only when the user asks to see the pet: a small desktop window that follows this tree's run (asleep, working, needs you, stopped at the limit, done); it opens and returns at once, and only reads · close it. `--demo` cycles the poses, `--pose <name>` shows one, `--still` keeps it still, `--exit-after <s>` is for tests; optional Python 3.8+ with tkinter |
| `council ledger` · `council ledger advice` · `council map status` · `council doctor` · `council tui` · `council history` · `council tune` | each seat's track record · what that record can support, with advice only past a bar · map freshness · drift scan with a fix per finding · a read-only terminal view of the run, for the user · every run's cost, estimate accuracy and catches, a rate only past five runs · proposals from that record, applied only with the user's words |
